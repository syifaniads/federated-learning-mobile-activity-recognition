# Team Attribution

## Collaborative project

This work was completed as part of a **Distributed Computing course project**. The final report combines evidence and analysis from **four groups** participating in the same Federated Learning exercise.

This personal repository exists to make the project understandable as portfolio evidence. It does **not** reassign collaborative source history or claim that every original file was written individually by the portfolio owner.

## Source ownership model

The portfolio distinguishes:

1. **course-level evidence** - results and screenshots contained in the final class report;
2. **group-level implementation** - code preserved in each group's original GitHub repository;
3. **portfolio documentation** - the recruiter-facing explanations, architecture summaries, result interpretation, and sanitized evidence in this repository.

## Why the code is not wholesale-copied here

Keeping the original collaborative source in its original repository preserves:

- author history;
- commit context;
- original project structure;
- team attribution.

This portfolio therefore links to the real source and only includes small portfolio-owned reference material where it improves explanation.

## Recruiter interpretation

The appropriate interpretation is:

> Participated in a collaborative distributed Federated Learning project and can explain the architecture, FedAvg aggregation, Non-IID behavior, Differential Privacy trade-offs, convergence, and communication experiments.

It should **not** be interpreted as:

> Solely authored every server, client, experiment, and report artifact across all four groups.
